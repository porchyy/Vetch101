# Vetch101: audit เพื่อจัดระเบียบโค้ด (2026-09-24)

## ขอบเขตและวิธีอ่าน

ตรวจรายการไฟล์ที่ติดตามด้วย `git ls-files` จำนวน 96 ไฟล์ ครอบคลุม frontend, Rust backend, tests/fixtures, release scripts, config/manifest, README/glossary/specs/research notes, และ issue notes ใน `.scratch/` 20 ไฟล์ รวมถึง `audio-spec.md` ที่ยังไม่ติดตามใน Git. ไฟล์ภาพไอคอนและ lockfiles ตรวจบทบาท/การอ้างอิง ไม่ตีความ binary หรือ dependency graph ทีละรายการ. ไม่รวมผล build, executable, `node_modules`, `temp`, และ `.agents/` ที่ถูก ignore ใน [.gitignore](../../.gitignore#L10). รายงานนี้เป็นการอ่านโค้ดและเอกสาร; ไม่ได้ทดสอบ GUI, live download, release หรือ installer ใหม่ จึงแยกความเสี่ยงที่ยังต้องพิสูจน์ไว้ชัดเจน.

## สิ่งที่ควรปรับก่อน (ยืนยันจากโค้ด)

1. **ทำให้ release มี input และ output ที่ตรวจสอบครบ.** [tauri.conf.json](../../src-tauri/tauri.conf.json#L27) แพ็ก engine จาก `dist-desktop/bin/*` แต่ [release.ps1](../../scripts/release.ps1#L44) ตรวจและคัดลอกเฉพาะ EXE/DLL/installer; ZIP จะใส่ `bin` ก็ต่อเมื่อโฟลเดอร์นั้นมีอยู่แล้ว ([บรรทัด 66](../../scripts/release.ps1#L66)). ดังนั้นสคริปต์ไม่ยืนยันว่า yt-dlp/FFmpeg ในแพ็กเป็นของชุด build นี้หรือมีครบจริง และอาจอาศัยไฟล์เก่าในเครื่อง build. กำหนดแหล่ง binary ที่แน่นอน ตรวจสามเครื่องมือก่อน build และก่อน zip, แล้วตรวจ archive/installer จากเครื่องสะอาด. [detector.rs](../../src-tauri/src/engine/detector.rs#L57) มี fallback ไป PATH/WinGet/Python จึงอาจปิดบังแพ็กที่ขาดเครื่องมือเมื่อ smoke test บนเครื่องพัฒนา.

2. **แก้ค่าคุกกี้ที่ค้างใน callback ดาวน์โหลดวิดีโอ.** `startDownload` อ่าน `browser` ตอนส่ง IPC ([useDownloadSession.ts](../../src/useDownloadSession.ts#L390)) แต่ dependency array ไม่มี `browser` ([บรรทัด 441](../../src/useDownloadSession.ts#L441)); หน้าแอปส่งค่าใหม่เมื่อเปลี่ยนตัวเลือก ([App.tsx](../../src/App.tsx#L130)). `inspectUrl` มี dependency นี้อยู่แล้ว ([useDownloadSession.ts](../../src/useDownloadSession.ts#L343)). เพิ่ม dependency และทดสอบการเปลี่ยนเบราว์เซอร์ระหว่าง inspect กับ download; React อธิบายว่า callback จำ closure ไว้จนกว่า dependencies จะเปลี่ยนใน [useCallback reference](https://react.dev/reference/react/useCallback).

3. **ให้การดาวน์โหลดรูปแจ้งเตือนครั้งเดียว.** [photo_downloader.rs](../../src-tauri/src/engine/photo_downloader.rs#L381) และ [commands.rs](../../src-tauri/src/commands.rs#L179) ต่างแสดง notification เมื่อ job สำเร็จ จึงมีสองจุดที่ทำหน้าที่เดียวกัน. เก็บไว้ที่ command boundary เช่นเดียวกับวิดีโอ ([commands.rs](../../src-tauri/src/commands.rs#L144)) แล้วลบอีกจุด.

4. **แยกการอ้างอิง release กับคู่มือพัฒนาให้ตรงกัน.** [README.md](../../README.md#L15) แสดงลิงก์/ชื่อไฟล์ 0.2.0 ขณะที่ manifest ปัจจุบันระบุ 0.2.2 ([package.json](../../package.json#L4), [Cargo.toml](../../src-tauri/Cargo.toml#L3), [tauri.conf.json](../../src-tauri/tauri.conf.json#L4)); ยังสรุปไม่ได้ว่า 0.2.2 ถูกเผยแพร่แล้ว. คำสั่ง test ใน README ชี้ `tests/video-input.test.mjs` ที่ไม่มีอยู่ ([README.md](../../README.md#L88)), และคำอธิบาย GNU target ไม่ตรงกับ target MSVC ใน [.cargo/config.toml](../../src-tauri/.cargo/config.toml#L2). ใช้ `npm test` เป็นคำสั่งอ้างอิง และแยก `current source version` ออกจาก `latest published release`.

5. **เอาเส้นทาง build ส่วนตัวออกจาก config ที่ commit.** [.cargo/config.toml](../../src-tauri/.cargo/config.toml#L3) กำหนด `target-dir` เป็น absolute path ของเครื่องหนึ่ง; clone ไปเครื่องอื่นอาจสร้างไฟล์ผิดที่หรือ build ไม่ได้. ให้ Cargo ใช้ค่าเริ่มต้น หรือกำหนด `CARGO_TARGET_DIR` ใน environment ของเครื่อง build ตาม [Cargo config reference](https://doc.rust-lang.org/cargo/reference/config.html#buildtarget-dir). [release.ps1](../../scripts/release.ps1#L22) อ่าน `target_directory` จาก `cargo metadata` อยู่แล้ว จึงไม่จำเป็นต้องฝัง path นี้เพื่อหาผล build.

6. **เลิกสำเนา script ที่ซ้ำกัน.** [run.bat](../../run.bat#L1) และ [start.bat](../../start.bat#L1) มีเนื้อหาเดียวกัน ขณะที่ [quick-run.bat](../../quick-run.bat#L1) เรียก `start.bat` อยู่แล้ว. เก็บ implementation เดียว; หากชื่อเก่ามีผู้ใช้ ให้เปลี่ยน `run.bat` เป็นตัวเรียก `start.bat` สั้น ๆ.

## งานจัดโครงสร้างที่ควรทำเมื่อเริ่ม refactor

- [App.tsx](../../src/App.tsx#L61) รวม dependency detection, engine/app update, folder preference, browser/theme/mascot preference และ JSX ในไฟล์เดียว 755 บรรทัด. ย้าย *เฉพาะ* updater/dependency orchestration ที่มี state และ effects ของตัวเองออกจาก presentation; ไม่ต้องสร้างชั้น service/config ใหม่. [useDownloadSession.ts](../../src/useDownloadSession.ts#L70) มี reducer และ side effects ใน 689 บรรทัด; reducer เป็น pure logic ที่ทดสอบได้อยู่แล้ว จึงควรคงไว้และแยกเฉพาะเมื่อลดการแก้ข้ามบริบทได้จริง. [MediaResultCard.tsx](../../src/components/MediaResultCard.tsx#L83) มี video/photo branches ในไฟล์เดียว 495 บรรทัด; แยก subview ตาม media type ได้โดยคง card shell และ props เดิม. [App.css](../../src/App.css#L1) ยาว 1,433 บรรทัดแต่จัดกลุ่มด้วย comments; split ตาม component ก็ต่อเมื่อย้าย JSX แล้วช่วยให้หา style ได้ง่ายขึ้น.
- [pipeline.rs](../../src-tauri/src/engine/pipeline.rs#L39) ถือ lock และ dispatch ไปสอง downloader; process supervision/format handling อยู่ใน [downloader.rs](../../src-tauri/src/engine/downloader.rs#L143) และ [photo_downloader.rs](../../src-tauri/src/engine/photo_downloader.rs#L234). ชื่อ/คำอธิบายว่า pipeline เป็นจุดจัดการทุกอย่างจึงกว้างกว่าบทบาทจริง ([pipeline.rs](../../src-tauri/src/engine/pipeline.rs#L24)). ถ้าจะคง layer นี้ ให้ระบุบทบาทว่า validate/lock/dispatch; ถ้าไม่มี caller อื่นหรือกฎร่วมเพิ่ม ให้พิจารณารวมเข้ากับ command แทน. ไม่ต้องสร้าง runner interface เพียงเพื่อให้โครงสร้างดูสมมาตร.
- [photo_extractor.rs](../../src-tauri/src/engine/photo_extractor.rs#L10) มี doc comment ซ้ำและบรรทัดแรกอ้าง `VideoMetadata` ที่ไม่ตรง return type. [photo_downloader.rs](../../src-tauri/src/engine/photo_downloader.rs#L222) มี public wrappers ที่ไม่พบ caller ใน repo (`run_photo_download`, `fetch_image_to_path`, `process_and_save_image`); [downloader.rs](../../src-tauri/src/engine/downloader.rs#L131) มี `run_download` แบบเดียวกัน และ [models.rs](../../src-tauri/src/models.rs#L99) มี `PhotoDownloadResult` ที่ไม่พบการใช้งาน. [open_external_url](../../src-tauri/src/commands.rs#L263) ลงทะเบียนใน [lib.rs](../../src-tauri/src/lib.rs#L61) แต่ไม่พบ caller ฝั่ง UI. ตรวจว่าไม่ใช่ public API ที่ใช้ภายนอกก่อนลบ; ไม่ต้องสร้าง abstraction แทน.
- ระวังความต่างระหว่างสเปกกับการทำงานปัจจุบัน: [docs/specs/codebase-architecture-deepening.md](../specs/codebase-architecture-deepening.md#L21) และ issue notes ใน `.scratch/codebase-architecture-deepening/issues/` เป็นเจตนา/ประวัติงาน ไม่ใช่หลักฐานว่า implementation ครบ. ข้อเสนอ refactor ควรอ้าง acceptance ที่ผู้ใช้ยืนยันล่าสุด: **พฤติกรรมเดิมต้องอยู่ครบ**.
- Issue notes ที่ติดตามใน `.scratch/` บางฉบับยังระบุ `ready-for-agent` เช่น [pixel-cat 01](../../.scratch/pixel-cat-mascot-and-dark-theme/issues/01-dual-theme-system.md#L7) และ [automatic-media-download 02](../../.scratch/automatic-media-download/issues/02-auto-inspect.md#L7) ทั้งที่มี theme และ auto-inspection ในโค้ด ([App.tsx](../../src/App.tsx#L77), [บรรทัด 505](../../src/App.tsx#L505)). ตรวจ acceptance ของแต่ละฉบับก่อนปรับสถานะเป็น done/archived; อย่าแก้สถานะทั้งหมดแบบเหมา.

## เรื่องที่ควรพิสูจน์ก่อนตัดสินใจแก้

- [README.md](../../README.md#L9) เรียก portable ว่า `100% Standalone`; [tauri.conf.json](../../src-tauri/tauri.conf.json#L27) ระบุเพียง `WebView2Loader.dll` ใน resources ไม่ได้ระบุ fixed WebView2 Runtime. Tauri อธิบายว่า installer ค่าเริ่มต้นจะดาวน์โหลด bootstrapper หาก runtime ไม่อยู่ในเครื่อง และมี fixed/offline options ใน [Windows installer guide](https://v2.tauri.app/distribute/windows-installer/#webview2-installation-options). นี่คือ caveat ของคำโฆษณา/การแพ็ก; ยังไม่มีหลักฐานว่า ZIP ใช้งานไม่ได้บน Windows 10/11 เป้าหมายจริง. ทดสอบบน VM สะอาดและปรับข้อความให้ตรงเงื่อนไข.
- [photo_downloader.rs](../../src-tauri/src/engine/photo_downloader.rs#L292) แปลง format ที่ไม่ใช่ `png` เป็น `jpg` เงียบ ๆ; [บรรทัด 299](../../src-tauri/src/engine/photo_downloader.rs#L299) ไม่ตรวจผลสร้าง temp directory. เป็นจุด validation/error handling ที่ควรใส่ใน regression เมื่อแตะเส้นทางรูป แต่ยังไม่พบ case พังจากการรันจริง.
- [scripts/release.ps1](../../scripts/release.ps1#L66) ไม่ตรวจ exit code ของ `tar` ก่อนรายงานสำเร็จ; พิสูจน์ด้วย release fixture/ZIP inspection แล้วเพิ่ม check เฉพาะจุด. [scripts/test-portable.ps1](../../scripts/test-portable.ps1#L91) ตรวจเปิดหน้าต่างและปิดแอปเท่านั้น; [native-smoke.mjs](../../scripts/native-smoke.mjs#L83) เป็น offline IPC smoke ที่แยกต่างหาก จึงอย่านับเป็นการยืนยัน download จากเว็บไซต์จริง.
