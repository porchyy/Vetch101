# Vetch101: วางลิงก์แล้วดาวน์โหลดรูปหรือวิดีโอได้ทันที

## Problem Statement

ผู้ใช้ต้องการเปิดแอป วางลิงก์ เห็นเนื้อหาที่จะได้ และกดดาวน์โหลดโดยไม่ต้องเรียนรู้เครื่องมือหรือเลือกโหมดก่อน ปัจจุบันต้องกดตรวจสอบลิงก์เองและพบตัวเลือกหลายอย่างก่อนดาวน์โหลด อีกทั้งตัวเลือกรูปภาพเดิมคือรูปปกคลิปแบบ JPG ไม่ใช่รูปทุกใบในโพสต์ TikTok

ผู้ใช้ต้องการให้แอปตรวจว่าโพสต์เป็นรูปภาพหรือวิดีโอเอง แล้วแสดงการดาวน์โหลดที่ตรงประเภท สำหรับรูปต้องเลือก PNG/JPG ได้และได้ความละเอียดสูงสุดที่ต้นทางเปิดให้เข้าถึง

## Solution

ใช้ช่องรับลิงก์เดียว วางหรือลากลิงก์แล้วเริ่มอ่านข้อมูลโดยอัตโนมัติ เมื่อพิมพ์เองให้รอจนหยุดพิมพ์และเป็นลิงก์ที่ถูกต้อง แสดงตัวอย่างก่อนเริ่มดาวน์โหลดจริง ผู้ใช้ยังต้องกดปุ่มดาวน์โหลด

- โพสต์วิดีโอ: แสดงปก ชื่อคลิป และปุ่มหลัก “ดาวน์โหลดวิดีโอ” โดยเลือกคุณภาพแนะนำให้อัตโนมัติ ตัวเลือกคุณภาพอื่น MP3 และโฟลเดอร์อยู่ใน “ตัวเลือกเพิ่มเติม”
- โพสต์รูป TikTok: แสดงรูป จำนวนและลำดับ มีตัวเลือก PNG/JPG และปุ่มดาวน์โหลดรูป ใช้ความละเอียดสูงสุดที่ดึงได้โดยไม่ให้ผู้ใช้เลือกขนาดเอง
- สถานะอ่านลิงก์ ดาวน์โหลด เสร็จสิ้น ยกเลิก และข้อผิดพลาดต้องอ่านเข้าใจง่าย เมื่อสำเร็จเปิดไฟล์หรือโฟลเดอร์ได้

ข้อกำหนดที่ผู้ใช้ระบุชัด: UI เรียบง่าย ช่องลิงก์ร่วม ตรวจประเภทอัตโนมัติ แยกหน้าดาวน์โหลดตามประเภท รูปความละเอียดสูงสุด และเลือก PNG/JPG ได้ ข้อเสนอที่ยังไม่ได้รับคำตอบโดยตรงอยู่ใน Further Notes

## User Stories

1. As a ผู้ใช้ทั่วไป, I want ช่องวางลิงก์ที่เห็นทันที, so that เริ่มใช้งานได้โดยไม่ต้องค้นหาเมนู
2. As a ผู้ใช้ทั่วไป, I want วางลิงก์แล้วแอปอ่านข้อมูลเอง, so that ไม่ต้องกดตรวจสอบลิงก์เพิ่ม
3. As a ผู้ใช้ที่ลากลิงก์จากเบราว์เซอร์, I want เริ่มอ่านข้อมูลเหมือนการวางลิงก์, so that ใช้งานได้สม่ำเสมอ
4. As a ผู้ใช้ที่พิมพ์ลิงก์เอง, I want แอปรอจนลิงก์พร้อมก่อนอ่านข้อมูล, so that ไม่เกิดคำเตือนระหว่างพิมพ์ทุกตัวอักษร
5. As a ผู้ใช้ TikTok, I want แอประบุว่าโพสต์เป็นรูปหรือวิดีโอ, so that ไม่ต้องเลือกโหมดเอง
6. As a ผู้ใช้วิดีโอ, I want รูปปกไม่ถูกนับเป็นโพสต์รูป, so that ได้ปุ่มดาวน์โหลดที่ตรงกับเนื้อหาจริง
7. As a ผู้ใช้ทั่วไป, I want เห็นตัวอย่างก่อนดาวน์โหลด, so that ตรวจได้ว่าวางลิงก์ถูกโพสต์
8. As a ผู้ใช้ทั่วไป, I want เห็นสถานะกำลังอ่านลิงก์, so that รู้ว่าแอปกำลังทำงาน
9. As a ผู้ใช้ที่เปลี่ยนลิงก์, I want ผลของลิงก์เก่าไม่แทนที่ลิงก์ใหม่, so that ไม่ดาวน์โหลดผิดโพสต์
10. As a ผู้ใช้วิดีโอ, I want ปุ่มดาวน์โหลดวิดีโอที่เด่นพร้อมคุณภาพแนะนำ, so that โหลดได้โดยไม่ต้องเข้าใจรูปแบบไฟล์
11. As a ผู้ใช้วิดีโอ, I want เปลี่ยนคุณภาพในตัวเลือกเพิ่มเติม, so that ยังควบคุมขนาดและคุณภาพได้เมื่อจำเป็น
12. As a ผู้ใช้เสียง, I want ตัวเลือก MP3 เดิมยังเข้าถึงได้, so that ยังใช้ความสามารถเดิมของแอปได้
13. As a ผู้ใช้โพสต์รูป, I want เห็นรูปทุกใบตามลำดับในโพสต์, so that ตรวจสอบอัลบั้มก่อนโหลดได้
14. As a ผู้ใช้โพสต์รูป, I want ดาวน์โหลดทั้งโพสต์ได้ด้วยปุ่มเดียว, so that ไม่ต้องบันทึกทีละรูป
15. As a ผู้ใช้โพสต์รูป, I want เลือก JPG หรือ PNG, so that ได้ไฟล์ที่เหมาะกับงานปลายทาง
16. As a ผู้ใช้ที่เน้นคุณภาพ, I want แอปเลือกภาพความละเอียดสูงสุดที่เข้าถึงได้, so that ไม่ต้องเดาว่าตัวเลือกใดชัดกว่า
17. As a ผู้ใช้ที่เน้นคุณภาพ, I want เก็บขนาดพิกเซลของภาพที่ดาวน์โหลด, so that ภาพไม่ถูกย่อโดยไม่จำเป็น
18. As a ผู้ใช้ JPG, I want หลีกเลี่ยงการบีบอัดซ้ำเมื่อไฟล์ต้นทางเป็น JPG ที่ใช้ได้อยู่แล้ว, so that ไม่เสียคุณภาพเพิ่มโดยไม่จำเป็น
19. As a ผู้ใช้ PNG, I want ได้ไฟล์ PNG จริงที่เปิดได้, so that โปรแกรมอื่นอ่านไฟล์ได้ถูกต้อง
20. As a ผู้ใช้โพสต์รูป, I want ชื่อไฟล์รักษาลำดับรูปและไม่เขียนทับไฟล์เดิม, so that จัดการภาพได้ง่ายและไม่เสียข้อมูล
21. As a ผู้ใช้ทั่วไป, I want ใช้โฟลเดอร์ที่เคยเลือกหรือโฟลเดอร์ดาวน์โหลดเริ่มต้น, so that ไม่ต้องเลือกปลายทางทุกครั้ง
22. As a ผู้ใช้ทั่วไป, I want เห็นความคืบหน้าจริงของงาน, so that รู้ว่าต้องรออีกหรือเกิดปัญหา
23. As a ผู้ใช้ทั่วไป, I want ยกเลิกงานได้, so that หยุดดาวน์โหลดที่ไม่ต้องการ
24. As a ผู้ใช้ที่โหลดไม่สำเร็จ, I want ข้อความสาเหตุที่เข้าใจได้และปุ่มลองใหม่, so that แก้สถานการณ์ต่อได้
25. As a ผู้ใช้ที่โหลดอัลบั้มสำเร็จบางรูป, I want รู้ว่ารูปใดสำเร็จและรูปใดล้มเหลว, so that ไม่เข้าใจผิดว่าได้ครบแล้ว
26. As a ผู้ใช้ทั่วไป, I want เปิดไฟล์หรือโฟลเดอร์หลังสำเร็จ, so that นำไปใช้ต่อได้ทันที
27. As a ผู้ใช้เดิม, I want ประวัติการดาวน์โหลดและลิงก์วิดีโอที่รองรับเดิมยังใช้ได้, so that การปรับ UI ไม่ทำให้ความสามารถเดิมหาย
28. As a ผู้ใช้คีย์บอร์ด, I want เข้าถึงช่องลิงก์ ตัวเลือก และปุ่มหลักได้พร้อมเห็นโฟกัส, so that ใช้งานได้โดยไม่ต้องใช้เมาส์
29. As a ผู้ใช้ Windows, I want แอปที่แพ็กแล้วใช้ความสามารถรูปได้โดยไม่ต้องลงเครื่องมือเอง, so that ยังคงเปิดโปรแกรมเดียวแล้วใช้งานได้
30. As a ผู้ใช้ที่พบลิงก์ไม่รองรับหรือเข้าถึงไม่ได้, I want แอปแจ้งให้ชัดแทนการโหลดรูปปกมาทดแทนอัลบั้ม, so that ไม่ได้ไฟล์ผิดประเภทโดยไม่รู้ตัว

## Implementation Decisions

- ใช้แอป Desktop และเส้นทางเรียกงานระหว่าง React กับ Tauri/Rust เดิม ปรับโมดูลรับลิงก์ อ่านข้อมูล ดาวน์โหลด แสดงผล และประวัติเท่าที่จำเป็น
- ข้อมูลโพสต์ต้องระบุประเภทวิดีโอหรือโพสต์รูปอย่างชัดเจน ข้อมูลรูปต้องมีรายการเรียงลำดับ ตัวตนของรูป ตัวอย่าง และขนาดพิกเซลเมื่อทราบ ผลลัพธ์ดาวน์โหลดต้องรองรับหลายไฟล์และความสำเร็จบางส่วน
- ตรวจประเภทจากข้อมูลเนื้อหาที่อ่านได้ ไม่ใช้การมีรูปปกหรือนามสกุล URL เป็นเกณฑ์เพียงอย่างเดียว ลิงก์สั้นต้องผ่านการแก้ปลายทางอย่างปลอดภัย หากระบุไม่ได้ให้รายงานข้อผิดพลาด
- ใช้กลไกยกเลิกผลตรวจลิงก์เก่าตาม revision ที่มีอยู่ รักษาการป้องกันงานซ้อน การยกเลิก และการเก็บกวาด process เดิม การเปลี่ยน/ล้างลิงก์ต้องทำให้ตัวอย่างเก่าหมดอายุทันที
- การอ่านข้อมูลอัตโนมัติไม่ใช่การดาวน์โหลดอัตโนมัติ ต้องกดปุ่มโหลดก่อนบันทึกไฟล์เนื้อหา
- เส้นทางวิดีโอใช้เครื่องมือเดิม ส่วนเส้นทางอัลบั้มต้องพิสูจน์ด้วยลิงก์จริงก่อนเลือก extractor ผลค้นคว้าพบ gallery-dl เป็นตัวเลือก แต่ยังไม่ได้ตัดสินใจเพิ่ม dependency และห้ามถือว่าการแปลง thumbnail เท่ากับรองรับอัลบั้ม
- “ความละเอียดสูงสุด” หมายถึงภาพเนื้อหาที่ดีที่สุดจากตัวเลือกที่เข้าถึงและตรวจสอบได้ในโพสต์นั้น ไม่รับรองไฟล์ก่อนอัปโหลดของเจ้าของภาพ ไม่ใช้ภาพตัวอย่างแทนโดยเงียบ และไม่ขยายพิกเซลเพื่ออ้างว่าคมชัดขึ้น ขนาดไฟล์อย่างเดียวไม่ใช่ตัววัดคุณภาพ
- ใช้เครื่องมือแปลงภาพที่มีอยู่ถ้ารองรับอย่างถูกต้อง เก็บพิกเซลและแนวภาพไว้ แปลง encoding จริงตาม PNG/JPG ไม่เปลี่ยนเพียงนามสกุล ถ้าต้นทางเป็น JPEG และต้องการ JPG ให้เก็บ bytes เดิมเมื่อเหมาะสม ส่วน JPG ที่จำเป็นต้องแปลงใช้คุณภาพสูงตาม encoder โดยไม่อ้างว่าไร้การสูญเสีย
- รักษาการตรวจ URL/redirect และปลายทางเครือข่ายที่เชื่อถือได้ ไม่เปิดให้ metadata ภายนอกสั่งอ่านไฟล์ในเครื่องหรือเข้าถึงปลายทางภายในโดยพลการ ตรวจขนาด/ชนิดไฟล์ ชื่อไฟล์ และโฟลเดอร์ก่อนบันทึก ไม่ส่ง credentials ใน log หรือประวัติ
- บันทึกไฟล์สำเร็จหลังตรวจไฟล์จริงเท่านั้น อัลบั้มรักษาลำดับและป้องกันชื่อชนกัน หากบางรูปเสียให้แสดงผลบางส่วนและลองใหม่อย่างไม่เขียนทับไฟล์ที่สำเร็จ
- คงฟังก์ชันเดิมที่เกี่ยวข้องไว้ในตำแหน่งรอง รวมถึงดาวน์โหลดปกที่มีอยู่ MP3 เปลี่ยนโฟลเดอร์ ประวัติ และอัปเดตเครื่องมือ รูปปกยังเป็นความสามารถคนละอย่างกับอัลบั้ม
- งานนี้ไม่มี schema ฐานข้อมูลหรือบริการ cloud ใหม่ หากขยายประวัติในเครื่องต้องอ่านรายการเดิมได้

## Testing Decisions

- จุดทดสอบหลักคือพฤติกรรมที่ผู้ใช้เห็นผ่านสัญญาการอ่านข้อมูล/เริ่มโหลด/ยกเลิกและเหตุการณ์ผลลัพธ์ของ Tauri เดิม ใช้จุดเชื่อมนี้จำลองต้นทางสำหรับการทดสอบซ้ำได้ แทนการสร้างจุด mock กระจายตามรายละเอียดภายใน
- ทดสอบพฤติกรรมภายนอก: ประเภทโพสต์ ตัวเลือกที่ปรากฏ ไฟล์ที่ได้ ความสำเร็จ/ล้มเหลว และการยกเลิก ไม่ล็อกชื่อ helper หรือลำดับการเรียกภายใน
- ใช้แนวทาง Node test runner เดิมสำหรับการรับลิงก์/state: วาง ลาก พิมพ์ ล้าง เปลี่ยนลิงก์ และผลตอบกลับผิดลำดับ รวมถึงเปลี่ยนจากอัลบั้มเป็นวิดีโอและกลับกัน
- ใช้ Rust tests เดิมและ fixtures ขนาดเล็กสำหรับการแปลง metadata การจัดการงาน การตรวจไฟล์และ output หลายไฟล์ ทดสอบทั้ง input ที่ใช้ได้และ metadata/ไฟล์เสีย
- ตรวจอัลบั้มรูปเดียวและหลายรูป: จำนวน ลำดับ และขนาดพิกเซลตรง metadata ที่ตรวจสอบได้ ตัวเลือกคุณภาพไม่ใช้ preview หรือขยายภาพแทนภาพจริง
- ตรวจ PNG/JPG ด้วยการเปิด/ถอดรหัสไฟล์จริงและตรวจชนิด encoding ไม่ดูนามสกุลอย่างเดียว ตรวจว่าการเก็บ JPEG เดิมไม่เปลี่ยน bytes และการแปลงไม่เปลี่ยนแนวหรือขนาดภาพโดยไม่ตั้งใจ
- ตรวจลิงก์ไม่ถูกต้อง โพสต์เข้าถึงไม่ได้ เครือข่ายขาด ไฟล์รูปเสีย การแปลงล้มเหลว การยกเลิกกลางอัลบั้ม และความสำเร็จบางส่วน ไม่แสดงสำเร็จครบหากยังมีรูปตกหล่น
- ทดสอบ UI จริงใน Desktop: วางลิงก์แล้วเห็นประเภทและปุ่มที่ถูกต้อง ไม่มีดาวน์โหลดก่อนกด โหลดแล้วเปิดไฟล์/โฟลเดอร์ได้ ใช้คีย์บอร์ดได้ และสถานะ/error อ่านเข้าใจง่าย
- แยก live smoke tests จาก offline regression: ใช้โพสต์สาธารณะที่เข้าถึงได้สำหรับวิดีโอ รูปเดี่ยว อัลบั้ม และลิงก์แชร์สั้น บันทึกเวลา รุ่นเครื่องมือ และผลจริง เนื่องจากบริการต้นทางเปลี่ยนได้
- ก่อนส่งมอบต้อง build frontend, รัน regression ที่เกี่ยวข้อง และทดสอบแพ็ก Windows ที่ใช้เครื่องมือครบโดยไม่อาศัย dev environment บนเครื่อง ห้ามนับผลจาก browser mock ว่าทดสอบดาวน์โหลด Desktop ผ่านแล้ว
- ได้ส่งแนวทางจุดทดสอบนี้ให้ผู้ใช้ตรวจความคาดหวังระหว่างจัดทำสเปก หากยังไม่มีคำตอบให้ถือเป็นข้อเสนอทางวิศวกรรม ไม่ใช่การยืนยันจากผู้ใช้

## Out of Scope

- อัปโหลดหรือโพสต์รูปต่อไปยังแพลตฟอร์มอื่นโดยอัตโนมัติ และรับประกันว่าเว็บไซต์ทุกแห่งรับไฟล์ได้
- AI upscale, retouch, ลบลายน้ำ หรือกู้รายละเอียดที่ต้นทางบีบอัดทิ้ง
- โหลดทั้งบัญชี ทั้งช่อง หลายโพสต์พร้อมกัน หรือระบบคิวจำนวนมาก
- ขยายอัลบั้มรูปไปทุกเว็บไซต์ในรอบนี้; เพิ่มอัลบั้ม TikTok และรักษาวิดีโอที่รองรับเดิม
- ระบบบัญชี/cloud sync และการเลี่ยงข้อจำกัดของโพสต์ส่วนตัว
- เปลี่ยนระบบอัปเดตทั้งชุดหรือรีแฟกเตอร์แอปที่ไม่จำเป็นต่อเส้นทางนี้

## Further Notes

- วันที่สังเคราะห์: 2026-09-19 จากการสนทนาและการตรวจโค้ด ยังไม่มีการแก้ตัวแอปสำหรับงานนี้ และยังไม่มี live photo-download verification
- คำศัพท์ในสเปก: “โพสต์รูป” คือเนื้อหาภาพหนึ่งใบหรืออัลบั้ม “รูปปก” คือภาพแทนวิดีโอ ทั้งสองไม่ใช่ประเภทเดียวกัน
- ข้อเสนอที่ยังไม่ได้รับการยืนยันโดยตรง: เลือกทุกภาพไว้เริ่มต้นแต่ยกเลิกเลือกบางภาพได้, ใช้ JPG ในครั้งแรกและจำ PNG/JPG ที่เลือกครั้งล่าสุด, ใช้คุณภาพวิดีโอที่ดีที่สุดซึ่งเข้ากับเส้นทาง MP4 เดิม ทั้งหมดเป็น working defaults ที่แก้ได้ ไม่ใช่คำตอบที่อ้างแทนผู้ใช้
- การเลือกบางภาพเป็นส่วนขยายที่เสนอ ไม่ควรทำให้เส้นทางโหลดทั้งอัลบั้มล่าช้าโดยไม่แจ้งผู้ใช้ หากจะนำออกจาก implementation ต้องระบุขอบเขตให้ชัด
- ขั้นดำเนินงาน: พิสูจน์การอ่านประเภท/โหลดรูปจริงและการแพ็กเครื่องมือ → ต่อสัญญาข้อมูลกับ UI ที่แยกตามประเภท → ตรวจ acceptance และ regression → แพ็กและทดสอบ Desktop
